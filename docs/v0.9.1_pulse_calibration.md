# v0.9.1: measured pulse-response calibration

The reported middle-joint extension moved from 117.74 to 58.45 degrees with
`pulse_on_ms=151`, exceeding the stored lower limit of 70.54 degrees. No gain
update was accepted (`fit_samples=0`). v0.9.1 replaces the long, monotonically
increasing pulses with a bounded adaptive pulse controller.

This is **not an LQR**. `JointStateModel::advance()` remains a telemetry predictor
with 1-ms integration steps and no authority over actuators. Each joint now also
stores separate flex/extend `PulseResponseModel` instances. Only an explicitly
armed ROM sweep uses a response model to select current for its next pulse.

## Defaults and stop conditions

All distances below are **motor encoder degrees**, not anatomical finger angles.
Settings live in `src/cpp/nml_hand_exo/config.h`.

| Setting | Default |
|---|---|
| Initial / minimum / maximum current | 40 / 5 / 160 mA |
| Maximum amplitude change per pulse | 6 mA, rounded to whole mA |
| Powered pulse duration / shape | 40 ms / eight 5-ms Gaussian bins |
| Minimum zero-current rest | 250 ms |
| Desired displacement per completed pulse | 0.65 degree |
| Position sampling service interval | 5 ms, during power and rest |
| Early current cutoff | 1 degree travel or 40 deg/s mean displacement rate since pulse start |
| Abort excursion | 3 degrees from pulse start, including unpowered coast |
| Settled speed / maximum rest wait | at most 1.5 deg/s / 1,500 ms |
| Post-pulse quiet position interval | 200 ms within a 0.18-degree range; sample gaps at most 50 ms |
| Per-direction sweep watchdog / SDK & GUI result wait | 45 / 55 seconds |
| Automatic return home | Disabled |

The minimum pulse/rest cycle is 290 ms (previously 430 ms). The next pulse
still waits for 200 ms of measured position stability and an acceptable velocity;
250 ms is a floor, not a fixed restart deadline. The displacement target is now
0.65 motor degree, below the unchanged 1-degree early cutoff.

Every pulse requires fresh position and velocity feedback, a settled joint, and
room inside the stored limits. Timeout, invalid feedback, excessive excursion,
or a position outside the stored window stops the campaign and disables the
target. Merely reaching the internal limit margin reports `status=limit`, with
no new endstop. The default finish/cancel path sends no return position goal.
`ROM_CAL_AUTO_RETURN_HOME` may explicitly enable the older return behavior for
non-fault outcomes; faults and cancellation never initiate a return.

The 40-ms shaped duration is a **cooperative-loop deadline**, not a hardware timer
guarantee. Actual write/read and scheduling delays remain observable through
`pulse_on_ms` and `max_pulse_on_ms`. More than 5 ms of overrun aborts. Zero current
does not actively brake inertia or gravity, so the travel thresholds are sampled
cutoffs, not guarantees that a physical joint cannot pass them. Shorter current
exposure and monitoring during coast address the previous failure; hardware
validation is still required. Neither calibration nor this model widens limits.

## Measured settling and encoder resolution

The previous 1-deg/s settle threshold was below one velocity-register count
(0.229 rpm, or 1.374 deg/s). Even a single nonzero count could therefore abort
an apparently stationary joint. ROM now accepts speed up to 1.5 deg/s, with an
additional post-pulse position check: measured positions must remain within
a 0.18-degree range for at least 200 ms. This range tolerates about two encoder
counts, while detecting oscillation as well as net drift. A sampling gap above
50 ms discards the old quiet interval. Every newly armed sweep starts with the
same zero-current rest and position-history gate before its first pulse. This
allows residual motion from the previous direction to settle within the normal
deadline, instead of immediately aborting on a single initial velocity reading.

After fitting and diagnostic output, firmware re-reads position and velocity
before applying the next pulse. If this fresh reading fails the settle gate,
it stays at zero current and waits within the original 1,500-ms rest deadline.
It does not count or fit the completed pulse again, or increase current again.
Persistent motion, invalid feedback, limits and excursion checks still stop
the sweep. These thresholds do not establish anatomical stillness; they operate
on measured motor-encoder feedback.

Final results add `velocity_deg_s`, signed `velocity_raw`, `settle_check`
(`rest` or `pulse_start`), `settle_span_deg` and `settle_quiet_ms`. These identify
which gate rejected the sample. A reset quiet window has a NaN span and zero
duration. A `not_settled` abort supplies no endstop and is not a gain update.

The initial current sign follows the gesture system's resolved absolute flexion
axis, including its profile-based override of a flip flag. The current writer's
flip is compensated exactly once. This prevents a short available window on one
side of home from making ROM drive toward that side while scoring progress in
the opposite direction. The measured wrong-direction guard still applies.

## Pulse shape and timing

`EXO_ROM_SHAPE_STEP_MS=5` (default) selects a midpoint-sampled Gaussian with
sigma 8 ms and peak-normalized weights:

| Time (ms) | 0-5 | 5-10 | 10-15 | 15-20 | 20-25 | 25-30 | 30-35 | 35-40 |
|---|---|---|---|---|---|---|---|---|
| Fraction of peak | 0.095967 | 0.309786 | 0.676634 | 1 | 1 | 0.676634 | 0.309786 | 0.095967 |

At 40 ms firmware writes zero. This is a piecewise-constant approximation.
At a 40-mA peak the rounded commands are 4, 12, 27, 40, 40, 27, 12, 4 mA,
then zero: 830 mA*ms exposure with exact 5-ms bins. Amplitude means peak current throughout
the configuration, adaptation and logs; shaping never scales up the peak to
preserve area. The shape uses a constant lookup table, without exponential
calculations or string serialization for the current updates.

Set `-DEXO_ROM_SHAPE_STEP_MS=10` alongside existing build flags for a four-bin
triangle approximation (1/3, 1, 1, 1/3, then zero). Firmware does not silently switch
profiles mid-campaign: that would change the amplitude-to-displacement mapping.
Skipping more than one scheduled shape slot aborts with `shape_overrun`.
A position read crossing the final deadline cuts current instead of writing a
late nonzero shape sample. The 5-ms schedule is separate from host polling;
actual bus/write timing still needs measurement under the intended load.

`RomPulseExposure` integrates the rounded signed commands between **completed**
write timestamps. It solves the unit-gain lag response per constant-current
interval, storing velocity `u`, displacement `z` and elapsed time `T`:

```
a = exp(-dt/tau)
z += I*dt + (u-I)*tau*(1-a)
u = I + (u-I)*a
```

With measured initial velocity `v0`, rest duration `R`, and measured total
travel `d`, the fitted gain is:

```
gain = (d - v0*tau*(1-exp(-(T+R)/tau))) /
       (z + u*tau*(1-exp(-R/tau)))
```

This includes coast, initial motion, shape, rounding and write scheduling jitter.
Completed-write timestamps approximate when the motor applied each register;
there is no measurement of the motor's internal current-loop response. The fit
still rejects configured load terms, saturation and inconsistent tail velocity.

## Prediction and bounded amplitude selection

The response model uses the measured signed displacement from the beginning of
the powered pulse to the end of its settling interval. Positive displacement
means progress in the requested direction. This includes motion during coast;
an off-phase timer alone is never counted as a stall or a moving sample.

For a moving observation at current magnitude `I_a` and displacement `d_a`, the
local prediction is:

```
predicted_displacement(I) = max(0, d_a + slope * (I - I_a))
```

The initial sensitivity is `d_a / I_a`, bounded to 0.001--1 degree/mA. When two
successive moving observations differ by at least 1.9 mA and 0.15 degree, a
positive secant gradient in that same range can update the slope. It is clipped
to 75--125% of the prior slope and blended by 25%, limiting each change to 6.25%.
The latest moving observation replaces the prediction's anchor. A negative or
too-small gradient is not used. Without sufficient excitation, the log continues
to identify the predictor as `ratio_seed`, rather than claiming a robust gradient.

The candidate current corrects the latest displacement error:

```
candidate = current + (target_displacement - observed_displacement) / slope
next = round(clamp(candidate, current - 6, current + 6, 5, 160))
```

Here `clamp` denotes both the per-step and absolute bounds. Errors within
0.15 degree hold the current. A no-motion observation instead permits only a
6-mA increase. An early travel/speed cutoff, or completed travel of at least
1 degree, reduces current by 6 mA. Early-cutoff pulses are excluded from the
fixed-duration response map. If the minimum current still produces a limited or excessive pulse, the campaign
aborts. A truncated pulse does not add stall evidence. Ordinary small deadline jitter is not normalized;
the map is a local empirical approximation, with actual duration in every log.

Displacements below the 0.3-degree motion threshold are **censored measurements**:
they mean no sufficient motion was observed. They increment `no_motion_samples`
and do not set gain to zero or provide an exact zero point for a gradient.
The observations cannot uniquely identify physical stiffness, friction, gravity,
inertia, and contact. Therefore `stiffness`, `moment`, and the time constant are
not automatically fitted from these pulses. The learned local sensitivity can
change as the joint moves; bounded corrections and measured travel checks remain
in force even when a prediction is poor. Each independently armed direction
starts conservatively with a fresh response model; its final statistics remain
in RAM for inspection until that direction is calibrated again or the board resets.

The existing lag-model gain fitter still runs on suitable moving responses using
the recorded shaped-command exposure and actual off duration. Its stricter validity checks are independent of the
local response map. This makes it possible for `response_samples` to increase
while the older `fit_samples` count remains zero.

## Diagnostics and Python interface

At zero current after a settled pulse, firmware emits an asynchronous
`ROM_CAL_PULSE` record containing:

- Peak current, actual duration, predicted/observed/target displacement.
- `shape`, `shape_step_ms`, and signed `exposure_mA_ms`.
- Learned slope, moving/no-motion/gradient counts, and `response_reason`.
- `fit_reason` for the separate lag-model gain fit and `pulse_stop` for the cutoff.
- `peak_excursion_deg`: largest sampled absolute displacement from pulse start, including coast.
- `pulse_end_delta_deg`: signed absolute encoder displacement sampled just after current is cut.
- `ceiling_no_motion_pulses`: consecutive full-ceiling low-response pulses.

Compare those excursion fields with `observed_deg` (settled displacement in the
requested direction) to distinguish little movement from movement followed by
recoil. Samples do not capture every point of the physical trajectory.

`predicted_deg=nan` means the local model has no moving observation yet, or
three consecutive sub-threshold responses have invalidated its old local
prediction. The learned slope is retained as a prior, not fitted to a fabricated
zero response. A new valid moving observation restores the prediction.
`fit_reason` distinguishes `insufficient_progress`, `velocity_unavailable`,
`velocity_limit`, `configured_load`, `tail_mismatch`, and other rejected-fit
conditions. `accepted` means the sample passed the mathematical fit; the
`ROM_CAL_UPDATE_MODEL_GAIN` setting still controls whether that fit is applied.
Fault results also include `max_excursion_deg` and the latest prediction/observation.

`ROM_CAL_RESULT endstop=nan` means no endstop candidate is available, including
limit/fault/timeout/current-ceiling outcomes. An endstop candidate now requires
at least three moving pulse responses, at least 1 degree of total progress, and
three consecutive full 160-mA pulses whose start/stop/settled positions collectively
stay within 0.18 degree. Early-cutoff pulses cannot provide stall evidence.
The earlier rule could mistake accumulated encoder-sized movements for meaningful
travel and declare an endstop while small pulses were still moving the joint.
At a stable ceiling without sufficient moving evidence, the result is `ceiling`.
Six consecutive full-duration pulses at the ceiling with settled displacement
less than 0.3 degree in magnitude instead report `status=ceiling` and
`reason=response_saturated`, even if earlier pulses moved the joint. This does
not provide an endstop. The stricter endstop test takes precedence when it
passes; continued useful movement can continue until the sweep watchdog.
Even the stricter rule is a contact heuristic, not proof of a physical endstop:
static friction or load can defeat the bounded pulses away from contact.
The operator must explicitly Apply reviewed results; stored limits remain enforced.

Results also include `net_travel_deg` (signed absolute encoder position minus
the starting position), `response_samples`, and `no_motion_samples`. The GUI
summarizes this travel, completed pulses and moving samples for each sweep, and
explains current-ceiling results. These are motor-encoder degrees, not anatomical
angles. `current_mA` and `exposure_mA_ms` describe commanded current, not an
independent measurement of the pulse's delivered current. The 40-ms shape,
starting peak is now 40 mA with 6-mA amplitude steps; the peak-current ceiling is now 160 mA.

`HandExo.get_joint_model(id)` adds `pulse_responses['flex'/'extend']`, containing
`slope`, `moving_samples`, `no_motion_samples`, and `gradient_samples`. The existing
five dynamics parameters remain available with unchanged names and units. Pulse
events use the async queue and are logged by the GUI; blocking `read_rom_result()`
skips/logs them while waiting for the final result. They cannot consume command
acknowledgements or cause the GUI to advance its ROM queue early.

Reflash with the existing Protobuf build flag (`compiler.cpp.extra_flags=-DEXO_USB_PROTOBUF=1`)
or the default build. `info` reports firmware **0.9.1**; the NX v2 telemetry and
`protobuf-v1` wire formats remain compatible. Restart the updated Python GUI.

## Verification

Native tests execute the actual ROM service with a deterministic bus/clock and
cover pulse timing, bounded amplitude, a stalled joint, a moving plant, gain
fitting, early cutoff, coast excursion, the reported outside-limit positions,
settling, one-count velocity and encoder jitter, persistent drift, transient
pre-pulse rechecks, feedback failures, watchdogs, and zero-current diagnostic emission.
An empirical dead-zone plant checks convergence toward the small displacement
target without large current steps. Python tests cover model metadata and
asynchronous pulse/result separation. These tests do not establish physical
accuracy or hard real-time timing on the exoskeleton.

## Assist mode

The new [Assist controller and GUI](assist_mode.md) use measured holding load
and deflection. Pulse-response calibration and assist are separate control modes;
a ROM gain fit does not calibrate gravity bias or turn on assistance.
